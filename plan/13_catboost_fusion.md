# 13 — CatBoost fusion selector with OOF training

## Role
Вы — Ranking/Fusion ML Engineer. Обучите простой CatBoost selector на leakage-safe OOF features и сравните его с RRF по Recall@50.

## Goal
Выбрать до 50 items из union pool, максимизируя validation Recall@50; сохранить classifier, feature schema, thresholds/config и honest evaluation.

## Context
Target pair-level: 1 для retrieved heldout relevant pair, 0 для retrieved weak negative. Primary baseline `CatBoostClassifier`; `CatBoostRanker` — optional bounded comparison, не presumed winner. Pair classification loss is proxy; model selection только по query-level Recall@50. Severe imbalance handled with retrieved negatives and modest weights/sampling, не giant random negatives.

## Prerequisites
- `12` OOF table verified, `11` RRF baseline and feature dictionary ready.
- Pool coverage upper bound sufficiently above RRF R@50 to justify selector; otherwise document retrieval bottleneck before tuning fusion.

## Inputs
- OOF feature table, fold/group/labels.
- Frozen validation candidate features generated by retrievers not trained on validation positives.
- `configs/catboost.toml`: feature list/order, classifier params, seed, class/sample weighting, iterations/depth/LR, early stopping protocol, top K=50.

## Tasks
1. Pin CatBoost dependency compatible with environment. Build typed feature matrix from feature dictionary; no ad hoc column discovery. Handle categorical features explicitly or keep safe scalar booleans/numerics.
2. Train `CatBoostClassifier` on OOF rows. For hyperparameter/early-stop evaluation, use group-aware split by `internal_query_id` and/or OOF fold; never random pair split that puts same query across train/eval.
3. Address imbalance via bounded retrieved negatives, class weights or per-query weighting. Compare a minimal set, report effect; ensure multi-positive/large-pool queries do not dominate contrary to mean-query Recall.
4. Score validation union candidates, sort probability desc with tie-break RRF desc then item_id, take up to 50 unique/query. Preserve queries with fewer candidates.
5. Evaluate canonical R@K/slices and compare RRF/BM25/dense/two-tower. Report pool upper bound and selector gap.
6. Compute feature importance (CatBoost native plus optional permutation only if cheap) for explanation, not causal claims. Audit suspicious dominance from ID/history/leakage; IDs cannot be model features.
7. Optional CatBoostRanker: run one controlled config only if group semantics valid and resources allow; same validation metric decides. Do not block classifier baseline.
8. Serialize/load fresh process and verify probability/top50 equivalence. Pin feature names/order/version in model manifest.
9. Define acceptance for selection: CatBoost chosen only if validation R@50 improves RRF beyond configured minimum and no unacceptable key-slice regression; otherwise final uses RRF, even if classifier loss/AUC looks good.
10. Fixed test remains untouched until model selection freeze in stage `14`.

## Architecture / Design Constraints
- Only OOF-generated training features.
- No raw IDs/text as CatBoost categorical shortcuts; only explicitly safe pair/item/query scalar features.
- No benchmark rows/labels.
- Training objective proxy; Recall@50 authoritative.
- Candidate pool not truncated destructively before scoring unless ablation selected.
- Seed/thread count recorded; CPU determinism checked.

## Interfaces / Data Contracts
Model bundle contains model file, `feature_dictionary.json`, source/preprocessing fingerprints, CatBoost version/config, training OOF hash, tie-break policy. Prediction output canonical ranking/candidates, source `catboost` or separate final schema.

## Tests
- Group-aware split has no query overlap.
- Feature column order enforced; missing/extra/incompatible dtype fails.
- ID/text/label/fold excluded from model feature list.
- Tiny imbalanced train→predict produces finite probabilities.
- Top-K uniqueness, fewer-than-K, ties deterministic.
- Serialize/load exact or tolerance-equivalent probabilities/ranks.
- Integration OOF table→model→validation candidates→evaluator.

## Verification
```bash
uv run pytest tests/fusion/test_catboost.py tests/integration/test_fusion_pipeline.py -q
uv run python -m avito_candidate_generation.fusion.catboost train --config configs/catboost.toml
uv run python -m avito_candidate_generation.fusion.catboost evaluate --config configs/catboost.toml --split validation
make ci
```
Required table: RRF vs classifier (and ranker if run), overall R@10/20/50, slices, pool R@500, selector gap, candidates/query. Validate feature allowlist, no query overlap, model reload equivalence and finite predictions.

## Expected Outputs / Artifacts
`artifacts/models/catboost/<run_id>/model.cbm`, feature dictionary, training/validation metrics, importance table, comparison report, model manifest/config.

## Documentation Requirements
Explain OOF necessity, retrieved-negative target caveat, imbalance/query weighting, tie-break, classifier-vs-ranker decision and why loss/AUC do not select model.

## Definition of Done
- Tests and `make ci` pass; bundle fresh-load works.
- Honest validation comparison and key slices available.
- Machine-readable decision CatBoost vs RRF made by Recall@50 acceptance.
- Gate 4 fusion candidate ready; test still untouched.

## Do Not
- Не train on in-sample retriever features.
- Не random-split pair rows.
- Не use `query_id`, `item_id`, raw text or historical popularity as shortcuts.
- Не select on AUC/logloss alone.
- Не assume Ranker beats Classifier.
